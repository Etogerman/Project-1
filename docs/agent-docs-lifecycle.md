# Жизненный цикл агентской документации

Этот файл описывает, как принимать изменения в документах, которые влияют на
действия агента.

## Когда применяется

Документ попадает под это правило, если он помогает агенту выбрать:

- что делать дальше;
- где остановиться;
- какой рабочий маршрут открыть;
- можно ли делать commit, push, PR, ready, merge, deploy или smoke;
- какую среду, адрес, callback, webhook или внешний контур использовать;
- какие ограничения применить к Bitrix24, Open Lines, Telegram, MAX или другому
  интеграционному контуру.

Обычная справка не попадает под это правило, если она не задаёт действие,
маршрут, ограничение или контрольную точку.

Этот файл применяется, когда агент создаёт, меняет, публикует или предлагает
повысить статус такого документа. Простое чтение активного документа для работы
по задаче не повышает уровень публикации и не требует отдельного разрешения.

## Статусы

`Черновик решения` — текст обсуждается в чате. Файлы не меняются.

`Локальный черновик` — текст внесён в файл локально. Он не опубликован, не
закоммичен и не является активным правилом.

`Локальный commit` — изменение зафиксировано в локальном commit. Оно не
опубликовано, не вынесено в PR и не является активным правилом.

`Опубликованная ветка` — ветка с изменением отправлена во внешний git-remote.
Это публикация кода документа, но ещё не предложение на review.

`Опубликованное предложение` — изменение вынесено в draft PR. Draft PR не делает
правило активным.

`Активное правило` — правило принято в активном контуре проекта. Для репозитория
это означает merge в активную ветку. Для агентской документации активная ветка
по умолчанию — `main`, если пользователь явно не указал другой активный контур.
Локальные черновики не становятся активными автоматически.

`Заменено` — правило больше не используется, потому что принято новое активное
правило.

Если статус документа неясен, агент использует более осторожный статус и
показывает это пользователю. Черновик не повышается до опубликованного
предложения или активного правила по догадке.

## Контрольные точки

Для документов, влияющих на действия агента, действуют отдельные уровни
разрешения:

1. Обсудить текст в чате.
2. Внести локальный черновик в файл.
3. Сделать commit.
4. Сделать push.
5. Открыть draft PR.
6. Считать правило активным после принятия в активный контур.

Каждый следующий уровень требует явного решения пользователя.

Перед commit для таких документов агент переносит изменение в clean docs-only
ветку или worktree от `origin/main`, если пользователь явно не указал другой
активный контур.

Этот перенос выполняется по `docs-only path` из `docs/task-delivery-workflow.md`.

Разрешение на локальный черновик не означает разрешение на commit.
Разрешение на commit не означает разрешение на push.
Разрешение на push не означает разрешение на draft PR.
Draft PR является опубликованным предложением, но не активным правилом.

Общие команды вроде `давай дальше` или `продолжай` не считаются разрешением на
повышение уровня публикации, если следующий уровень прямо не назван.

## Следующий шаг

Если агент предлагает действие с таким документом, пункт меню должен прямо
называть уровень разрешения:

- внести локальный черновик;
- сделать commit;
- сделать push;
- открыть draft PR;
- оставить без публикации.

Агент не использует общие формулировки вроде `продолжить`, если следующий шаг
меняет уровень публикации.

## Отчёт агента

При handoff агент явно сообщает:

- текущий статус документа;
- является ли документ активным правилом;
- практический статус: локально, зафиксировано, опубликовано или PR;
- какой следующий уровень требует решения пользователя.

## Конфликты

Если чат, локальный черновик, draft PR и активное правило расходятся, агент
показывает расхождение пользователю и использует активное правило до нового
явного решения.

Агент не выбирает новую версию молча.
