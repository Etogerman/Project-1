# UI Patterns — обязательные правила для агента-разработчика

> Этот документ — **жёсткий контракт** на внешний вид. Если Codex
> отрисовывает экран и **не использует** правила отсюда — он
> делает не то, что нужно, и работу придётся переделывать.
>
> Источник правды по цветам/типографике/радиусам/теням: **`design/tokens.css`**.
> Готовые компоненты с этими токенами: **`design/base.css`**.
>
> Перед тем как писать вёрстку, открой и просмотри:
> - `design/tokens.css` — что есть в палитре и шкале;
> - `design/base.css` — какие компоненты уже готовы;
> - `design/Карточка контакта.html` — образец **карточки сущности** (двух-колоночный layout, секции, поля);
> - `design/Справочник полей.html` — образец **настройки + таблицы + правой панели**.
>
> Любой новый экран в проекте — это **сборка из существующих кирпичей**,
> а не «творчество». Всё, что отсюда не покрыто — спроси, не выдумывай.

---

## 0. Что нельзя делать никогда

1. **Не подключать сторонние UI-фреймворки** (Filament, Bootstrap,
   Material, Tailwind preset, daisyUI и т.д.). У нас есть `tokens.css`
   и `base.css` — других CSS-зависимостей быть не должно.
2. **Не использовать классы из чужих фреймворков** в вёрстке
   (`fi-*`, `fi-fo-*`, `fi-sc-*`, `bs-*`, `mat-*`, `wire:*` как стиль и т.п.).
   Если такие классы пришли из админ-генератора — они должны быть
   полностью переписаны в `ac-*` / локальные `xx-*` префиксы под наш
   экран.
3. **Не вводить собственные цвета и шрифты.** Любой `#hex`, `rgb()`,
   `oklch()` в продакшен-CSS, **не пришедший из `tokens.css`** — ошибка.
4. **Не использовать `!important`**, не делать inline-стили
   с произвольными цветами, размерами шрифта, radius, тенями.
5. **Не использовать иконочные шрифты (Font Awesome / Heroicons-веб-фонт).**
   Только inline-SVG (см. примеры в `Карточка контакта.html`,
   `Справочник полей.html`).
6. **Не использовать эмодзи в UI.** Никаких 🔍 ⚙️ ✅ ❌ ⚠️ — рисуем SVG.
7. **Не вставлять «декоративный» вспомогательный текст**: «Здесь
   вы можете…», «Этот раздел предназначен для…», «Пожалуйста,
   обратите внимание…» — это мусор. CRM-плотность.
8. **Не делать «воздушных» layout-ов** с огромными padding-ами и
   крупными шрифтами «как на landing page». Это плотная B2B-CRM.
   Базовый размер текста — 13px, заголовок страницы — 22px,
   высота строки таблицы — 40px.

## 1. Anatomy экрана

Любая страница продукта имеет одинаковый каркас:

```
ac-app                            ← grid: sidebar | (topbar / main)
├─ ac-sidebar                     ← левая навигация, всегда видна
├─ ac-topbar                      ← хлебные крошки + ⌘K + уведомления + аватар
└─ ac-main                        ← контент страницы
   └─ ac-page                     ← max-width: 1280, padding 20×24
      ├─ ac-page-head             ← h1 + meta + правые actions
      ├─ ac-tabs (optional)       ← подвкладки страницы
      ├─ (тулбар страницы)        ← search + filter-buttons + count
      ├─ (содержимое: секции/таблица/канбан)
      └─ ac-page-footer (optional)
```

**Точные классы и их состав см. в `design/base.css`** (`.ac-app`,
`.ac-topbar`, `.ac-sidebar`, `.ac-nav__item`, `.ac-page`, `.ac-page-head`,
`.ac-tabs`, `.ac-section`, `.ac-field-row`, `.ac-btn`, `.ac-badge`,
`.ac-tag`, `.ac-channel`, `.ac-avatar`, `.ac-mono`, …).

---

## 2. Типографика — фиксированная шкала

Не вводи новые размеры. Шкала жёсткая (см. `--ac-fs-*` в tokens):

| Размер | Когда |
|---|---|
| **22px / 700** | h1 страницы. Один на страницу. |
| **15px / 600** | заголовки модалок и больших секций. |
| **13px / 500–600** | основной текст, кнопки, label поля, имя в строке таблицы. |
| **12px / 500** | мета-инфа, второстепенные подписи, лейблы полей в карточке. |
| **11px / 600 + uppercase + letter-spacing 0.06em** | THEAD таблицы, заголовки секций сайдбара (`UPPERCASE`). |
| **10–10.5px / 700** | бейджи uppercase. |

Шрифт: системный стек из `--ac-font`. Моноширинный — только для
**технических токенов** (ID, ключ поля, IP, переменные, телефон): `.ac-mono`.

Не использовать `letter-spacing` нигде кроме uppercase-меток.

---

## 3. Цвет — только токены

Все цвета идут через CSS-переменные. **Никаких хардкодов**.

- Текст: `--ac-text` (основной), `--ac-text-2` (вторичный), `--ac-text-3` (placeholder/мета).
- Поверхности: `--ac-bg` (страница), `--ac-surface` (карточка),
  `--ac-surface-2` (hover, secondary), `--ac-surface-3` (active).
- Линии: `--ac-border`, `--ac-border-strong`, `--ac-border-input`.
- Акцент: `--ac-accent` + `--ac-accent-soft` + `--ac-accent-ring` (focus).
- Семантика: `--ac-success`, `--ac-warning`, `--ac-danger`, `--ac-info` (+ их `*-soft`).
- Каналы связи (Telegram, MAX, Bitrix24): `--ac-channel-tg`, `--ac-channel-max`, …
- Теги: `--ac-tag-gray|blue|green|yellow|red|purple` (+ их `*-soft`).

Если цвета не хватает — **значит ты делаешь не то**. Проконсультируйся
с пользователем, не «угадывай» новый.

---

## 4. Готовые компоненты — что брать

Перед тем как писать новый компонент, посмотри в `design/base.css` —
наверняка уже есть. Базовый перечень:

| Класс | Что |
|---|---|
| `ac-btn` (`--primary`, `--ghost`, `--danger`, `--success`, `--sm`, `--lg`) | Кнопка. Высоты: 26 / 30 / 36. |
| `ac-icon-btn` | Иконочная кнопка 30×30, без фона. |
| `ac-tabs` + `ac-tab` (`is-active`) + `ac-tab__count` | Подвкладки страницы. |
| `ac-section` + `ac-section__head` + `ac-section__body` | Стандартная карточка-секция с заголовком. |
| `ac-field-row` + `ac-field-row__label` + `ac-field-row__value` | Плотная строка «label : value» с inline-edit. |
| `ac-badge` (`--success`, `--warning`, `--danger`, `--info`, `--accent`) | Статус-пилюля. |
| `ac-tag` (`--gray|blue|green|yellow|red|purple`) | Тег с цветной точкой. |
| `ac-channel` (`--tg|max|tgacc|b24`) | Чип канала связи. |
| `ac-avatar` (`--sm|md|lg|xl`, `--tone-1..6`, `--muted`, `--placeholder`) | Аватар с инициалами / фото / placeholder. |
| `ac-mono` | Инлайн-моно-чип для тех. токенов. |
| `ac-breadcrumb` / `ac-topbar__crumb` | Хлебные крошки. Всегда **в топбаре**, не в контенте. |
| `ac-savebar` (`is-visible`) | Плавающая sticky-панель «Сохранить / Отмена». |
| `ac-stack`, `ac-stack-3`, `ac-stack-2`, `ac-row`, `ac-row-wrap`, `ac-grid-2`, `ac-spacer` | Утилиты компоновки. |

Если **не хватает** — оформи новый компонент локально с префиксом
страницы (например, `sp-` для «Справочник полей»), используй
только токены из `tokens.css`. **Никаких новых глобальных классов
без согласования.**

---

## 5. Плотность

Это **CRM**, не блог.

- Высота строки таблицы: 40px (`--ac-row-h-table`).
- Высота строки в карточке (label : value): 32px (`--ac-row-h`).
- Высота кнопок: 26 / 30 / 36.
- Базовый внутренний padding секции: `10px 14px`.
- Базовый зазор между секциями в стэке: 16px (`--ac-sp-4`).
- Базовый зазор между крупными блоками (page → tabs → content): 20px (`--ac-sp-5`).

Padding страницы — **20×24** (`--ac-page-pad-y` × `--ac-page-pad-x`).
Контент сужать до `--ac-content-max = 1280px`.

Не делать пустых вертикальных пробелов >24px между элементами.

---

## 6. Таблицы — образец

См. `design/Справочник полей.html` → класс `sp-table`.

Правила:
- Заголовок строки THEAD — `10px / 600 / uppercase / letter-spacing 0.06em`,
  цвет `--ac-text-3`, sticky `top: 0`, нижняя граница `1px solid --ac-border`.
- Тело — `font-size: 13px`, `height: 40px`, разделитель — `border-bottom: 1px solid --ac-border`,
  **без вертикальных линий**, hover-фон `--ac-surface-2`.
- Drag-handle / kebab / copy — **появляются только на hover** строки (opacity: 0 → 1).
- Выбранная строка: фон `--ac-accent-soft`, левая полоса `inset 3px 0 0 --ac-accent`.
- Системные/read-only поля помечать **маленьким SVG-замком** рядом
  с лейблом, не словом «read only».
- Числовые колонки выравнивать вправо, моно-шрифт через `ac-mono`
  или семейство `--ac-font-mono`.

---

## 7. Формы — образец

См. `design/Справочник полей.html` → drawer (`sp-drawer`, `sp-form-row`).

- Высота инпута/селекта по умолчанию — **32px**.
- Радиус — `--ac-radius-2` (6px).
- Рамка — `--ac-border-input` → focus: `--ac-accent` + `box-shadow: 0 0 0 3px --ac-accent-ring`.
- Лейбл сверху, `12px / 500`, цвет `--ac-text-2`.
- Подсказка под полем — `11px / --ac-text-3`, **одна строка по делу**, не три.
- Тогглы — 32×18, дорожка `--ac-surface-3`, активная `--ac-accent`.
- Чекбоксы — 16×16, рамка `1.5px --ac-border-strong`, активный
  заполнен `--ac-accent`, галка — белый SVG `path "m3.5 8.5 3 3 6-7"`.
- Селект — без нативной стрелки, через `background-image: svg`.

---

## 8. Иконки

- Только **inline-SVG**, `viewBox="0 0 20 20"` или `0 0 16 16`.
- `stroke="currentColor"`, `fill="none"` (если outlined),
  `stroke-width: 1.6` (нав) или `1.8` (контролы) или `2` (плюс).
- Размер: 14×14 в кнопках, 16×16 в иконочных кнопках, 12–13×… в чипах.
- Цвет — `currentColor` от родителя. Не задавать `stroke` цветом-токеном
  напрямую — это делает иконку «несменяемой» в hover/active.
- Никаких иконок-PNG/JPG.

Образцы — в `Карточка контакта.html` и `Справочник полей.html`.

---

## 9. Состояния

| Состояние | Как показать |
|---|---|
| Пустое значение поля | `<i class="ac-empty"></i>` → отрисует «—» цветом `--ac-text-3`. |
| Hover на строке | фон `--ac-surface-2`, **никаких** transform/scale. |
| Active/pressed | фон `--ac-surface-3`. |
| Focus (клавиатура) | `box-shadow: 0 0 0 3px var(--ac-accent-ring)`. |
| Disabled | `opacity: 0.5; pointer-events: none;` (см. `.ac-btn[disabled]`). |
| Required | маленькая красная точка (`var(--ac-danger)`), не звёздочка. |
| Read-only/системное | мини-SVG-замок рядом с лейблом. |

---

## 10. Хлебные крошки

- Живут **в топбаре** (`ac-topbar__crumb`), а не в контенте страницы.
- Разделитель — `›` цвета `--ac-text-3`.
- Последний сегмент — `--ac-text` + `font-weight: 600`.
- Динамические крошки (карточка диалога открыта из контакта vs. из
  списка диалогов) — определяются props/route source, не хардкодом.

---

## 11. Drawer / правая панель деталей

Когда экран — это **список + детали**, открывай детали в правом drawer-е,
а не в модалке.

См. `design/Справочник полей.html` → `sp-drawer`.

- Ширина: 420px (на узких экранах — 360px).
- Top: `var(--ac-topbar-h)` (drawer не перекрывает топбар).
- Bottom: 0.
- Граница слева `1px var(--ac-border)`, тень — `-8px 0 24px rgba(15,23,42,.04)`.
- Footer drawer-а с кнопками «Удалить / Отмена / Сохранить» — sticky.
- При открытом drawer — основная область получает `padding-right`
  равный ширине drawer-а + `--ac-page-pad-x`, чтобы контент не уехал
  под него.

---

## 12. Save bar

Когда пользователь редактирует поле inline или меняет настройку —
показывай **плавающую панель внизу по центру** (`.ac-savebar.is-visible`),
а не модалку с подтверждением.

Состав: пульсирующая warning-точка + текст «Есть несохранённые изменения»
+ кнопки «Отмена» / «Сохранить» (primary).

---

## 13. Темная тема

Все цвета берутся из переменных, и `[data-theme="dark"]` уже определён в
`tokens.css`. Не пиши параллельную CSS-ветку под тёмную — это
делается одним переключателем атрибута на `<html>`.

---

## 14. Что отдавать, чтобы прошло ревью

1. **HTML без сторонних классов.** Только `ac-*` (общие) и `xx-*`
   (локальные под страницу). Никаких `fi-*`, `wire:*`,
   фреймворковых утилит.
2. **Один глобальный CSS-файл** или связка `tokens.css` + `base.css`
   + локальный `<style>` под страницу. Любые новые токены — в `tokens.css`
   и с обоснованием.
3. **Никаких inline `style="color:#..."` с произвольным цветом.**
   inline-style допустим, если значение — токен (`color:var(--ac-text-3)`)
   или геометрия (`width:280px`).
4. **Иконки только inline-SVG**, без эмодзи и иконо-шрифтов.
5. **Плотность как в образцах.** Сверь высоты строк/кнопок/инпутов
   с разделом «Плотность».
6. **Карточка / список / форма — собраны из готовых классов**,
   а не нарисованы с нуля.

## 15. Образцы (открой в браузере перед работой)

| Файл | Что показывает |
|---|---|
| `design/Карточка контакта.html` | Карточка сущности: шапка с аватаром, статы, табы, две колонки секций, ac-field-row, телефоны, теги. |
| `design/Справочник полей.html` | Список-таблица в настройках, тулбар с поиском и фильтрами, чипы-группы, drawer деталей с формой, сохраняющая панель. |
| `Конструктор бота.html` (через `app.jsx`) | Полный продуктовый интерфейс: канбан диалогов, контакты, конструктор сценария. Опорный набор для визуального тона. |

Если что-то нужно отрисовать, а в образцах этого нет, — **спроси**,
не выдумывай. См. `AGENT_GUIDE.md` § 4.3 «Чего не нужно делать».
