# Внешнее ревью ТЗ исправления

Загружайте этот модуль только для состояния `P03`.

## `P03` — Внешнее ревью ТЗ исправления

Исполнители review: Claude и Gemini независимо. Запуск, получение результатов
и техническую квалификацию выполняет агент без передачи пользователю роли
курьера.

Оба reviewer-а получают один проверяемый снимок и не видят выводы друг друга.
Launcher читает единственный [канонический prompt](external-spec-review-prompt.md).
Внешний ответ принимается только после проверки identity, структуры,
доказательств и применимости каждого finding.

До preflight launcher эксклюзивно создаёт технический marker начала preflight;
до запуска двух полных review — `started.json` с полной identity. Повторный
`run-id`, секрет в снимке или непустой accepted `results/` блокируют CLI-вызов.

| № | Проверяемый результат | Следующее состояние | Исполнитель перехода |
|---:|---|---|---|
| 1 | Оба review выполняются, событие завершения обоих процессов ещё не наступило | `P03` | Агент и reviewer-ы |
| 2 | Подтверждён технический пробел в текущем объёме | `C07` | Агент |
| 3 | Подтверждено изменение продукта, риска или объёма | `D01` | Агент → пользователь |
| 4 | Reviewer или доступ недоступен, timeout истёк, ответ повреждён либо identity не совпала; сохранить `return_state=P03` | `B01` | Агент |
| 5 | Пользователь подтвердил окончательную отмену; дочерние процессы завершены, accepted results пусты, `stop_mode=final_cancellation` | `X03` | Пользователь → агент |
| 6 | Два валидных review завершены, подтверждённых P0/P1/P2 нет | `C09` | Агент |

Оба процесса запускаются параллельно. После их завершения агент продолжает
квалификацию в текущей задаче; отдельное сообщение пользователя не требуется.
Отмена пользователем возвращает отдельный статус `cancelled_by_user`, а не
маскируется под timeout или повреждение ответа.

Task-local цикл хранит отдельные ревизии ТЗ, отдельные снимки запусков и один
проверенный итоговый набор. Авторское ревью не попадает в reviewer-root.
Launcher создаёт только `claude.md` и `gemini.md`; сводный вывод формирует агент.
Технически успешный launcher остаётся в `P03` с признаком обязательной
квалификации. Переход в `C09` фиксирует только агент после сводного вывода.
Сводный вывод содержит identity того же запуска отдельной строкой. Повторная
финализация того же набора безопасно завершает прерванный cleanup.
