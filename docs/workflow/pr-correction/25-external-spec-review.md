# Внешнее ревью ТЗ исправления

Загружайте этот модуль только для состояния `P03`.

## `P03` — Внешнее ревью ТЗ исправления

Исполнитель review: Claude. Запуск, получение результата и техническую
квалификацию выполняет агент без передачи пользователю роли курьера.

Claude получает один проверяемый снимок и не получает прежние review-ответы.
Launcher читает единственный [канонический prompt](external-spec-review-prompt.md),
чьи точные байты закреплены SHA-256 в исполняемом модуле. Внешний ответ
принимается только после проверки identity, структуры, доказательств и
применимости каждого finding.

`review-manifest.json` строго связывает base/head, снимки деревьев, ТЗ,
авторское ревью, prompt, версию и настройки официального Claude CLI,
исполняемый файл и политику процесса. Identity — SHA-256 канонического JSON без
поля `identity`; лишние или отсутствующие поля запрещены.

До preflight launcher эксклюзивно создаёт технический marker начала preflight;
до полного review — `started.json` с полной identity. Повторный `run-id`, секрет
в снимке или непустой accepted `results/` блокируют CLI-вызов. Непосредственно
перед spawn повторно проверяются настройки, исполняемый файл, secret scan,
запрет MCP и каталог capture. OAuth token удаляется из каждого chunk до записи;
обнаружение токена блокирует результат.

| № | Проверяемый результат | Следующее состояние | Исполнитель перехода |
|---:|---|---|---|
| 1 | Review выполняется, событие завершения процесса ещё не наступило | `P03` | Агент и Claude |
| 2 | Подтверждён технический пробел в текущем объёме | `C07` | Агент |
| 3 | Подтверждено изменение продукта, риска или объёма | `D01` | Агент → пользователь |
| 4 | Reviewer или доступ недоступен, timeout истёк, ответ повреждён либо identity не совпала; сохранить `return_state=P03` | `B01` | Агент |
| 5 | Пользователь подтвердил окончательную отмену; дочерний процесс завершён, accepted results пусты, `stop_mode=final_cancellation` | `X03` | Пользователь → агент |
| 6 | Валидный review Claude завершён, подтверждённых P0/P1/P2 нет | `C09` | Агент |

После завершения Claude агент продолжает квалификацию в текущей задаче;
отдельное сообщение пользователя не требуется. Отмена пользователем получает
отдельный статус `cancelled_by_user`, а не маскируется под timeout или
повреждение ответа.

При исходе `blocked` или `cancelled_by_user` launcher до возврата результата
атомарно сохраняет копию исходного terminal evidence и связанный с текущими
cycle, revision, run и review-снимком `terminal-result.json`. Та же transaction
переводит active cycle из `P03` соответственно в `B01` или `X03` и сохраняет
holding-frame с `return_state=P03`; успешный CLI-ответ без этой фиксации
запрещён.

Task-local цикл хранит отдельные редакции ТЗ, отдельные неизменяемые запуски и
один проверенный итоговый набор. Авторское ревью хранится в корне редакции и не
попадает в `review-root`. До квалификации stdout Claude находится только в
`capture/`, а `results/` пуст.

Атомарный переход `C08 → P03` создаёт в новом review-run только
`run-open.json`. Launcher после проверки этого файла самостоятельно создаёт
`review-manifest.json` и `launch-intent.json`; второй владелец этих файлов
запрещён.

Ответ Claude имеет строгий формат: identity первой непустой строкой, затем
ровно четыре именованных раздела с JSON-массивами findings, проверенной и
непроверенной области и вычисляемым вердиктом. После проверки ответа агент одной
transaction intent создаёт `qualification.json`, `consolidated.md`, при исходе
`C09` — весь `review-final`, и выполняет CAS `P03` в вычисленное состояние.

В `results/` атомарно появляются ровно три файла: `claude.md`,
`qualification.json`, `consolidated.md`. Каталог `review-final/` содержит ровно
семь файлов: ТЗ, авторское ревью, ответ Claude, квалификацию, сводный вывод,
review-manifest и итоговый manifest. Повтор той же операции с совпадающими
identity является идемпотентным успехом; расхождение ведёт в `B01`.

Git- и CLI-команды выполняются без shell, с отдельными argv, deadline, лимитом
вывода, отдельной группой процессов и завершением всей группы. MCP и неизвестные
долгоживущие потомки ведут в `B01`. Gemini в этом контуре не запускается, его
настройки не читаются и review-артефакты для него не создаются.
