# Реализация, проверка и публикация исправления

Загружайте этот модуль только для состояний `C10`, `C11`, `G01` или `C12`.

Модуль не расширяет предел исполнения. Локальная реализация, commit и push —
разные уровни разрешения.

## `C10` — Локальная реализация

Исполнитель: агент.
Обязательный шлюз: `implementation / G00 / implementation-gate.json`.

Результат: изменение выполнено строго по итоговому ТЗ исправления `C09` после
успешной проверки `G00`.

| № | Проверяемый результат | Следующее состояние | Исполнитель перехода |
|---:|---|---|---|
| 1 | Реализация завершена по итоговому ТЗ исправления | `C11` | Агент |
| 2 | Реализация выявила пробел в ТЗ исправления | `C07` | Агент |
| 3 | Реализация требует расширить объём работ или изменить риск | `D01` | Агент → пользователь |
| 4 | Возникла техническая блокировка вне контроля агента; сохранить `return_state=C10` | `B01` | Агент |

## `C11` — Локальные тесты и авторская проверка

Исполнитель: агент.
Обязательный шлюз: `implementation / G00 / implementation-gate.json`.

Результат: регрессия воспроизведена, исправление доказано, применимые проверки
зелёные, выполнена авторская проверка итогового локального diff.

| № | Проверяемый результат | Следующее состояние | Исполнитель перехода |
|---:|---|---|---|
| 1 | Найдена ошибка реализации | `C10` | Агент |
| 2 | Найдена ошибка или неполнота ТЗ исправления | `C07` | Агент |
| 3 | Проверки выявили выход за согласованный объём | `D01` | Агент → пользователь |
| 4 | Не хватает обязательного локального доказательства; сохранить `return_state=C11` | `B01` | Агент |
| 5 | Регрессия, исправление и применимые проверки подтверждены | `G01` | Агент |

## `G01` — Граница публикации исправления

Исполнитель: агент.
Обязательный шлюз: `implementation / G00 / implementation-gate.json`.
Обязательное доказательство перехода: `G01 -> C13 / publication_noop / G01 / no-op-proof.json`.

Проверяются текущий предел исполнения, необходимость commit/push, применимость
Spec repo / Spec doc / Spec revision и отсутствие неразрешённых внешних
действий.

Вход `C11 → G01` выполняет операция `enter_publication_boundary`: она проверяет
implementation gate и решение из неизменяемого ledger, одной transaction intent
создаёт новый publication run, записывает в него только `run-open.json`,
устанавливает `activeRunId` и меняет active cycle. `publication-gate.json` на
этом шаге ещё не существует и создаётся только после запечатывания дерева,
успешных проверок и классификации внешнего ТЗ ниже.

`G01` строит отдельный Git index от `publishBase`, включает ровно разрешённые
изменения и удаления, блокирует чужой diff и получает `expectedTreeOid`.
До первой Git-команды канонический realpath и repository identity переданного
repo сверяются с source context активного publication run; другой checkout или
fork запрещён даже при совпадающих base и списке файлов.
Проверки выполняются в изолированном checkout именно этого tree и записываются
в строгий `checks-manifest.json`; shell, командная строка вместо argv и
неуспешная проверка запрещают публикацию.

После успешных проверок создаётся отдельная
`publication-spec-classification.json`. Для мутирующего пути `G01` выдаёт
строгий `publication-gate.json`, связанный с implementation gate, обеими
классификациями, exact tree/diff, списком файлов и checks. `pending` не создаёт
gate: оформляется `B01` с владельцем, событием появления проверенной Spec
revision и `return_state=G01`; возобновление создаёт новый publication run.

| № | Проверяемый результат | Следующее состояние | Исполнитель перехода |
|---:|---|---|---|
| 1 | Изменяемого diff нет; опубликованный снимок не изменился | `C13` | Агент |
| 2 | Commit и push разрешены, применимый Spec-контур синхронизирован | `C12` | Агент |
| 3 | Предел исполнения заканчивается до commit или push; сохранить `resume_state=C12` | `D02` | Агент → пользователь |
| 4 | Обязательный внешний Spec или другое доказательство публикации недоступно; сохранить `return_state=G01` | `B01` | Агент |

Прямой `G01 → C13` допустим только для настоящего no-op и требует отдельный
`no-op-proof.json`: remote HEAD равен `publishBase`, remote tree и
`expectedTreeOid` совпадают, binary/full-index diff пуст, checks зелёные, а
publication classification имеет решение `not_required` или `fixed` без
неопределённости. `publication-gate.json` и `no-op-proof.json` в одном run
взаимоисключающи.

## `C12` — Commit и push исправления

Исполнитель: агент только в пределах явного разрешения.
Обязательный шлюз: `publication / G01 / publication-gate.json`.

Результат: новый удалённый head опубликован либо оформлена именованная
блокировка.

Commit создаётся только из запечатанного index или воспроизведённого index с
тем же tree. До push повторно проверяются HEAD tree, base, diff, обе
классификации, checks и identity publication gate.

| № | Проверяемый результат | Следующее состояние | Исполнитель перехода |
|---:|---|---|---|
| 1 | Commit и push текущего исправления успешны | `C13` | Агент |
| 2 | Commit создан, но push не разрешён; сохранить `resume_state=C12` и `requested_action=push` | `D02` | Агент → пользователь |
| 3 | До публикации найдена ошибка реализации | `C10` | Агент |
| 4 | Push разрешён, но технически недоступен; сохранить `return_state=C12` | `B01` | Агент |
