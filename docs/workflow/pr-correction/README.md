# Цикл исправления открытого PR

Это единственный маршрут обработки нового сигнала об ошибке в открытом PR до
merge.

## Когда цикл применяется

Входом в `C01` считаются:

- красный или неоднозначный CI;
- замечание самостоятельного или стороннего review;
- новое или повторно открытое обсуждение;
- ошибка процессной проверки, метаданных PR или полей готовности;
- блокирующая проблема авторской самопроверки.

Цикл применяется к draft и ready PR в `staging` и `main`. Для
docs-only/process-only PR применяется выбранный пользователем контур проверки;
пакет двух независимых проверок от этого обязательным не становится. Дефект
после merge, обнаруженный на smoke или QA, открывает маршрут исправления релиза
либо новый stream.

## Как выбрать модуль

Не загружайте все документы цикла. Выполните:

```bash
node .github/scripts/workflow-docs-check.mjs --state <ID>
```

Команда вернёт название, исполнителя, допустимые следующие состояния и один
канонический документ. Прочитайте этот документ полностью. При переходе
повторите команду для нового ID.

## Запись состояния при передаче шага

```text
Цикл исправления: <ID — название>
Результат квалификации: <точный результат>
Следующее состояние: <ID — название>
Исполнитель: <агент | пользователь | внешний сервис | назначенный владелец>
Условие перехода: <проверяемое событие>
```

Фразы `ждём`, `позже` или `нужны данные` без ID, владельца, условия
разблокировки и состояния возврата запрещены. `B01`, `B02`, `D02` и `X03`
сохраняют `return_state` либо явный выход. `P01` и `P02` сохраняют внешний
статус, владельца следующего возврата и проверяемое событие завершения.

## Префиксы состояний

- `C` — работа агента;
- `D` — решение или ручное действие пользователя;
- `G` — граница публикации;
- `P` — внешняя проверка;
- `B` — именованная блокировка;
- `X` — выход из цикла.

## Приоритет результатов

Если одновременно видны несколько результатов, сначала применяется `D01` для
решения по объёму или риску, затем `B01/B02` для обязательной блокировки, затем
возврат к сбору доказательств и только после этого успешный переход.

## Контрольные сценарии

| Сценарий | Обязательная трасса |
|---|---|
| Необоснованное замечание на draft | `C01 → C02 → C03 → C04 → C13 → P01 → D03 → P02 → C14 → X01` |
| Необоснованное замечание уже делегированного снимка | `C01 → C02 → C03 → C04 → C13 → P01 → P02 → C14 → X01` |
| Не хватает доказательств | `C01 → C02 → B01 → C02 → C03`; при отмене — `B01 → X03` |
| Дефект в текущем объёме | `C01 → C02 → C03 → C07 → C08 → C09 → C10 → C11 → G01 → C12 → C13 → P01 → D03 → P02 → C14 → X01` |
| Выход за объём работ | Продолжение PR: `C01 → C02 → C03 → D01 → X02 → C07`; отдельный stream: `C01 → C02 → C03 → D01 → X02 → X03` |
| Красный CI после исправления | `C12 → C13 → P01 → C01 → C02 → C03` |

Точные условия переходов определяют только четыре модуля, указанные в
[маршрутизаторе](../README.md).
