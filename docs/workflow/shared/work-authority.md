# Полномочия, потоки и передача шага

Этот модуль читается перед любым действием, которое может изменить файлы,
git-состояние, окружение или внешний контур. Он дополняет короткую конституцию
из `AGENTS.md` и не даёт разрешения сам по себе.

## Полномочия

1. Анализ, review, критика, сравнение, план и подготовка ТЗ выполняются только
   для чтения.
2. Код, конфигурация, тесты, документация, git-состояние и окружения меняются
   только по явной команде пользователя и в пределах согласованного ТЗ.
3. Локальная правка, commit, push, создание PR, внешняя мутация и deploy —
   отдельные уровни полномочий. Разрешение одного уровня не разрешает следующий.
4. GitHub-контрольные действия выполняет только пользователь: ready/draft,
   merge, закрытие или повторное открытие PR, approve/request changes/dismiss,
   environment approval, branch protection, required checks, secrets и rules.
5. Перед внешним действием агент проверяет исполнителя, предел полномочий,
   точную цель и требуемую контрольную точку.

## Активные потоки и хвосты

1. По умолчанию одновременно активен один существенный code/release stream.
2. Параллельно допустимы docs-only/spec/admin tail и cleanup, если они не
   затрагивают runtime diff и не повышают предел исполнения code stream-а.
3. Перед новым существенным code/release stream проверяется хвост предыдущего:
   локальный diff, незапушенные изменения, PR, CI, rollout, cleanup и follow-up.
4. Второй code stream требует отдельного решения пользователя. Должны быть
   названы primary/secondary, отдельные рабочие копии и пределы исполнения;
   запрещены общий deploy blocker, пересечение rollout/ownership и маскировка
   release-tail основного stream-а.
5. Изменения разных stream-ов не переносятся между worktree молча.

## Неопределённость и блокировка

1. При неоднозначности агент сначала исчерпывает безопасные способы получить
   факты в режиме только чтения.
2. Нехватка данных не превращается в безымянное ожидание. Блокировка содержит:
   недостающее доказательство или действие, владельца, проверяемое событие
   разблокировки и состояние возврата.
3. Выход за согласованный объём, продуктовый выбор и принятие нового риска
   передаются пользователю как отдельное решение.
4. Для сигнала открытого PR применяется состояние из
   [цикла исправления](../pr-correction/README.md); вне него используется
   контрольная точка профильного процесса.

## Авторская проверка и передача шага

1. Каждый законченный slice завершается короткой авторской проверкой.
2. Полная авторская проверка обязательна на смысловой, рискованной и
   публикационной границе, а также для окончательного опубликованного снимка PR.
3. В handoff указываются: фактический результат, локальный или опубликованный
   статус, текущий этап, блокировки, следующий исполнитель и проверяемое событие
   перехода.
   Время указывается абсолютной датой, временем и часовым поясом; относительные
   формулировки без абсолютной отметки не используются как доказательство.
4. Агент называет следующий этап процесса, даже если для его исполнения нужна
   отдельная команда пользователя. Контрольная точка ограничивает действие, но
   не подменяет следующий шаг.
5. Меню показывается только при реальном выборе, запросе разрешения, блокировке
   или передаче мяча пользователю. Один точный следующий шаг формулируется прямо.

Точная матрица исполнителей находится в
[`docs/action-ownership.md`](../../action-ownership.md).
