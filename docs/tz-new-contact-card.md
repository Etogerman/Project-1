# ТЗ: Новая карточка контакта

## Цель

Заменить текущую карточку контакта (модальное окно, одна колонка) на полноценную страницу с двухколоночным макетом по образцу Битрикс24. Поэтапно добавить таймлайн, комментарии оператора и историю изменений.

## Текущее состояние

- Карточка контакта — модальное окно (`ViewAction` в Filament, ширина 7xl)
- 8 секций в одну колонку: контакт, дедупликация, профиль, теги, диалоги, анкета, работа с контактом, телефоны
- Два сворачиваемых раздела: подробности, диагностика вебхука
- Все действия через Livewire-модалки в `ManageContacts.php` (976 строк)
- Таймлайна нет
- Комментариев оператора нет

## Целевое состояние

### Макет страницы

### Вкладки

1. **Общее** (по умолчанию) — двухколоночный макет: секции слева, таймлайн справа
2. **Диалоги** — список диалогов контакта по каналам связи (Telegram, MAX — отдельная карточка на каждый канал). Карточка диалога: канал, последнее сообщение, время, кнопка «Открыть»
3. **Битрикс24** — все `bitrix24_*` поля контакта (спецификация полей — см. Приложение А)

Вкладка «История изменений» — не утверждена, откладывается до решения по хранению событий.

### Шапка

- Кнопка «Назад» (возврат к списку контактов)
- Имя контакта (`display_name`) — крупно
- Платформа основной идентичности (значок Telegram/MAX)
- Основной телефон (копируемый)
- Канал
- Ответственный (или «Свободен»)
- Статус синхронизации с Битрикс24

### Левая колонка — секции

Секции сверху вниз (все сворачиваемые):

1. **Профиль** — имя, фамилия, пол, возраст, возрастная группа, дата рождения, страна, город, регион, статус региона, расстояние до Москвы, статус расстояния. Кнопка «Редактировать» → модальное окно
2. **Телефоны** — список телефонов с источником и признаком основного. Кнопки: добавить, редактировать, удалить
3. **Теги** — список тегов. Кнопки: добавить, снять
4. **Анкета** — текущий шаг, попытки, известные данные. Кнопка «Возобновить» (если доступно)
5. **Работа с контактом** — ответственный, автоответы (вкл/выкл), удаление контакта
6. **Дедупликация** — только если есть дубли или открытые проверки
7. **Подробности** — свёрнуто по умолчанию: ID, внешний ID, имя пользователя, параметры старта, количество сообщений, дата создания
8. **Диагностика вебхука** — свёрнуто по умолчанию: последний внешний ID, ключ события, сырой payload

### Правая колонка — таймлайн

Лента событий в обратном хронологическом порядке (новое сверху):

| Тип события | Источник данных | Описание в ленте |
|-------------|-----------------|------------------|
| Комментарий оператора | Новая таблица (этап 3) | Текст комментария, автор, время |
| Синхронизация с Битрикс24 | Существующие данные: `bitrix24_sync_logs` | «Контакт синхронизирован», «Сделка создана», «Ошибка синхронизации» |
| Завершение анкеты | Существующие данные: `contacts.data_collection_completed_at` | «Анкетирование завершено» |
| Смена ответственного | Новая таблица (этап 3) | «Ответственный изменён: Иван → Мария», автор |
| Появление нового диалога | Существующие данные: `dialogs.created_at` | «Новый диалог: Telegram / Канал X» |
| Создание контакта | Существующие данные: `contacts.created_at` | «Контакт создан» |

### Технические подписи полей

Временное решение для разработки: под каждым полем показывается его технический ключ в формате `snake_case`. Это не операторский интерфейс — убирается или прячется за переключатель после завершения разработки.

## Этапы реализации

### Этап 1: Каркас страницы

**Цель:** перейти с модального окна на полноценную страницу с двухколоночным макетом.

**Что делается:**
- Новая страница `ViewContact` вместо модального `ViewAction`
- Шапка с основной информацией
- Двухколоночный макет: левая (≈40%) и правая (≈60%)
- Левая колонка: перенос текущих секций без изменения содержимого
- Правая колонка: каркас (заглушка «Таймлайн»)
- Вкладки: Общее (активная), Диалоги (перенос текущей секции), Битрикс24 (поля по Приложению А)
- Все текущие действия (модалки) работают как раньше
- Обновление ссылки из списка контактов на новую страницу

**Что не делается:**
- Таймлайн
- Новые таблицы и модели
- Изменение бизнес-логики

**Критерии приёмки этапа 1:**
- Карточка открывается как отдельная страница
- Двухколоночный макет отображается
- Три вкладки работают
- Все текущие действия доступны
- Модальное окно карточки больше не используется

### Этап 2: Таймлайн (только чтение)

**Цель:** заполнить правую колонку лентой событий из существующих данных.

**Что делается:**
- Сервис `BuildContactTimelineAction` — сборка ленты из нескольких существующих источников
- Правая колонка: лента событий (создание контакта, появление диалогов, завершение анкеты, синхронизация Битрикс24)
- Все данные берутся из существующих таблиц, новых таблиц нет

**Что не делается:**
- Комментарии оператора
- Запись новых событий
- Новые миграции

**Критерии приёмки этапа 2:**
- Лента показывает события из существующих данных
- Обратный хронологический порядок
- Каждое событие: тип, описание, время

### Этап 3: Комментарии оператора

**Цель:** дать оператору возможность оставлять комментарии к контакту.

**Что делается:**
- Решение по хранению (таблица `contact_timeline_entries` или другое)
- Модель `ContactTimelineEntry`
- Миграция
- Сервис `AddContactTimelineCommentAction`
- Поле ввода комментария вверху таймлайна
- Комментарии появляются в ленте
- Сервис `RecordContactTimelineEventAction` — запись системных событий
- Добавить вызовы записи в: назначение ответственного, завершение анкеты, синхронизация

**Критерии приёмки этапа 3:**
- Оператор может написать и сохранить комментарий
- Комментарий виден в ленте
- Системные события (смена ответственного и др.) записываются и видны в ленте

### Этап 4: История изменений (отложен)

Не утверждён. Требует отдельного решения по:
- Источнику данных (как отслеживать изменения полей)
- Ретроспективности (старые изменения не восстановить без аудит-лога)
- Формату отображения

## Что не меняется (для всех этапов)

- Страница диалога (рабочее место оператора) — остаётся как есть
- Список контактов — остаётся, ссылка ведёт на новую страницу
- Вся бизнес-логика (синхронизация, анкетирование, автоответы)
- Права доступа — те же проверки, тот же набор разрешений

## Тестовая стратегия

- Функциональные тесты на новую страницу: загрузка, отображение секций
- Тесты на каждую вкладку
- Тесты на таймлайн: сборка ленты, порядок событий
- Тесты на комментарии (этап 3)
- Существующие тесты модалок — адаптировать под новую страницу

## Известные компромиссы

- Таймлайн на этапе 2 показывает только данные из существующих таблиц. Смены ответственного до этапа 3 не отображаются (нет источника).
- `ManageContacts.php` (976 строк) потребует существенной переработки при переносе на страницу. Возможно деление на несколько Livewire-компонентов.
- Ретроспективная история изменений полей невозможна без аудит-лога. Решение откладывается.

## Приложение А: Спецификация полей Contact

### Правила форматирования

- `string|null`: строка или «—»
- `bool`: доменный текст, а не `true/false`
- `date`: `d.m.Y`
- `datetime`: `d.m.Y H:i:s`
- `int|null`: число или «—»
- `enum`: текущий человекочитаемый форматировщик проекта
- `json/array`: компактный список значений через запятую; если пустой — «—»

### Вкладка «Общее»: поля

**Базовые**
- `ID` (`id`): bigint, системный ID контакта
- `Имя (мессенджер)` (`name`): string?, имя из мессенджера, приходит из входящих сообщений
- `Ответственный` (`assigned_user_id`): foreignId?, показывается имя сотрудника
- `Автоответы` (`is_auto_reply_enabled`): bool, включены ли автоответы
- `Создан` (`created_at`): datetime
- `Обновлён` (`updated_at`): datetime

**Профиль**
- `Имя` (`first_name`): string?, вручную или анкетирование
- `Фамилия` (`last_name`): string?, вручную
- `Пол` (`gender`): enum?, вручную или автоопределение из имени
- `Возраст (эффективный)` (`effective_age_years`): int?, вычисляемое из `birth_date` или `age_years`
- `Возраст (ручной)` (`age_years`): int?, точное значение
- `Возрастной диапазон` (`age_range`): enum?, вручную или анкетирование
- `Дата рождения` (`birth_date`): date?, вручную

**Локация**
- `Страна` (`country`): string?, вручную или анкетирование
- `Город` (`city`): string?, вручную или анкетирование
- `Регион` (`region`): string?, вручную, ИИ или подтверждение контактом
- `Статус региона` (`region_status`): enum?
- `Источник региона` (`region_source`): enum?
- `Кандидаты региона` (`pending_region_candidates`): array?

**Расстояние**
- `Расстояние до Москвы` (`distance_to_moscow_km`): int?
- `Статус расчёта` (`distance_to_moscow_status`): enum?
- `Расстояние рассчитано` (`distance_to_moscow_calculated_at`): datetime?

**Анкета**
- `Статус анкеты` (`data_collection_status`): enum?
- `Текущий шаг` (`data_collection_current_field`): enum?
- `Последний заданный шаг` (`data_collection_last_prompted_field`): string?
- `Анкета начата` (`data_collection_started_at`): datetime?
- `Текущий шаг начат` (`data_collection_current_field_started_at`): datetime?
- `Анкета завершена` (`data_collection_completed_at`): datetime?
- `Попыток` (`data_collection_attempts_count`): int

**Дедупликация**
- `Статус дедупликации` (`duplicate_review_status`): enum
- `Основной контакт` (`merged_into_contact_id`): foreignId?, показывается имя root-контакта
- `Склеен` (`merged_at`): datetime?
- `Причина` (`merge_reason`): string?
- `Триггерный телефон` (`merge_trigger_phone`): string?

### Вкладка «Битрикс24»: поля

**Контакт**
- `ID контакта в Битрикс24` (`bitrix24_contact_id`): string?
- `Статус синхронизации контакта` (`bitrix24_sync_status`): enum
- `Контакт синхронизирован` (`bitrix24_last_synced_at`): datetime?
- `Контакт привязан` (`bitrix24_linked_at`): datetime?
- `Синхронизация в очереди` (`bitrix24_sync_pending`): bool
- `Отпечаток синхронизации` (`bitrix24_sync_fingerprint`): string?

**Сделка**
- `ID сделки в Битрикс24` (`bitrix24_deal_id`): string?
- `Статус синхронизации сделки` (`bitrix24_deal_sync_status`): enum
- `Сделка синхронизирована` (`bitrix24_deal_last_synced_at`): datetime?
- `Сделка привязана` (`bitrix24_deal_linked_at`): datetime?
- `Синхронизация сделки в очереди` (`bitrix24_deal_sync_pending`): bool

**История**
- `Статус выгрузки истории` (`bitrix24_history_sync_status`): enum
- `История выгружена` (`bitrix24_history_last_synced_at`): datetime?
- `Выгрузка истории в очереди` (`bitrix24_history_sync_pending`): bool
