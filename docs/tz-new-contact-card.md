## Шапка страницы

### Состав шапки

Шапка содержит:
- кнопку `Назад к контактам`
- главный заголовок карточки
- кнопку `Редактировать`

### Правило формирования заголовка

Главный заголовок строится из полей контакта по правилу:
- основа: `last_name` + `first_name`
- порядок: `Фамилия Имя`
- если заполнено только одно из полей, показывается оно
- если оба поля пустые, используется fallback `Имя (мессенджер)`

### Роль шапки

Шапка решает две задачи:
- навигация
- быстрое открытие редактирования профиля

Технические подписи полей в операторском интерфейсе не показываются. Если они понадобятся для отладки, это оформляется отдельным dev/debug-режимом и не входит в базовый UI-контракт.

- поля, которые уже были видны в карточке

Итоговое правило:
- все non-bitrix поля `Contact` находятся на вкладке `Общее`

## Вкладка `Диалоги`

Вкладка `Диалоги` показывает карточки диалогов контакта по каналам связи.

### Правило группировки

- одна карточка = один `Dialog`
- так как `Dialog` уникален на пару `[contact_id, channel_id]`, в норме это означает одну карточку на канал

### Состав карточки диалога

Карточка диалога показывает:
- платформу и/или канал
- имя канала
- route context или внешний chat id, если это полезно
- preview последнего сообщения
- `last_message_at`
- `last_inbound_at`
- `last_outbound_at`

### Действие карточки

- `Открыть диалог`

### Empty state

Если у контакта нет диалогов, вкладка показывает пустое состояние.

## Вкладка `История`

Вкладка `История` показывает timeline истории событий контакта.

### Роль вкладки

Вкладка даёт оператору последовательность значимых событий по контакту.

На первом этапе эта вкладка показывает историю событий контакта, а не полный audit всех изменений полей.

### Состав timeline на этапе 2

Timeline включает high-signal события состояния контакта:
- создание контакта
- появление нового диалога у контакта
- получение телефона контакта
- старт анкеты
- завершение анкеты
- merge / склейка контакта
- значимые события Bitrix24 sync

### Правило по сообщениям

Timeline включает только события состояния контакта; сообщения остаются в dialog page.

### Событие `Появился диалог у контакта`

Это отдельный тип события timeline.

Он используется в двух сценариях:
- создан новый `Dialog`
- после объединения контактов у root-контакта стал доступен дополнительный диалог

Для этапа 2 действует честный контракт:
- обычное появление диалога строится из существующего источника `dialogs.created_at`
- merge-сценарий получает отдельное событие только при наличии подтверждённого источника в runtime
- если отдельного источника нет, merge-кейс отображается через событие merge

### Пагинация timeline

- первая порция: 20 последних событий
- следующая порция: ещё 20 событий
- порядок: обратный хронологический
- способ загрузки: кнопка `Показать ещё`
