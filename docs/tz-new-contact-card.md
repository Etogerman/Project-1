# ТЗ: Новая карточка контакта

## Цель шага

Перевести карточку контакта из modal-only сценария в отдельную page-level страницу `ViewContact` с layout по мотивам Битрикс24.

Итоговый экран должен дать оператору:
- отдельную страницу контакта вместо модального окна
- понятную шапку контакта
- вкладки `Общее`, `Диалоги`, `Битрикс24`, `История`
- рабочую двухколоночную вкладку `Общее`
- полноширинные вкладки `Диалоги`, `Битрикс24` и `История`

При этом доменный принцип сохраняется:
- `Contact` остаётся обзорной карточкой клиента
- `Dialog` остаётся основным рабочим местом оператора для переписки

## Границы

### Что меняется

- основной путь открытия контакта переводится на page-level страницу
- карточка получает новую шапку, вкладки и layout
- вкладка `Общее` собирает текущие рабочие блоки контакта и все non-bitrix поля `Contact`
- вкладка `Диалоги` показывает диалоги контакта по каналам связи
- вкладка `Битрикс24` показывает CRM-данные контакта
- вкладка `История` показывает timeline событий контакта

### Что сохраняется

- бизнес-логика `Contact`, `Dialog`, collector, dedup и Bitrix24 sync
- dialog page как рабочее место оператора
- существующие права доступа
- текущая доменная модель на этапах 1 и 2

### Следующие темы оформляются отдельными этапами

- комментарии оператора в ленте
- полная история изменений полей в формате `old -> new`
- reply composer внутри карточки контакта
- перенос полного чата в карточку контакта
- новые Bitrix24 сценарии вне текущего подтверждённого happy-path

## Текущее состояние

- карточка контакта открывается через `ViewAction` как модальное окно
- контент карточки собран в одну колонку
- overview-блоки контакта уже существуют
- dialog page уже вынесена как отдельный экран
- отдельной вкладки истории у контакта сейчас нет

## Вкладка `Общее`

Вкладка `Общее` является основным экраном карточки контакта.

### Правило состава вкладки

Вкладка `Общее` объединяет все прямые поля `Contact`, кроме `bitrix24_*`.

Во вкладке одновременно присутствуют:
- поля, которые сейчас уже видны в карточке
- поля, которые сейчас находятся в скрытых или служебных блоках
- связанные рабочие блоки `Телефоны` и `Теги`

Итоговое правило для страницы:
- все non-bitrix поля `Contact` находятся на вкладке `Общее`
- эти поля доступны оператору сразу в составе открытых секций

### Левая колонка

## Вкладка `Диалоги`

Вкладка `Диалоги` показывает карточки диалогов контакта по каналам связи.

### Правило группировки

- одна карточка = один `Dialog`
- так как `Dialog` уникален на пару `[contact_id, channel_id]`, в норме это означает одну карточку на канал

### Состав карточки диалога

Карточка диалога показывает:
- платформу и/или канал
- имя канала
- route context или внешний chat id, если это полезно
- preview последнего сообщения
- `last_message_at`
- `last_inbound_at`
- `last_outbound_at`

### Действие карточки

- `Открыть диалог`

### Empty state

Если у контакта нет диалогов, вкладка показывает пустое состояние.

## Вкладка `Битрикс24`

Вкладка `Битрикс24` показывает CRM-данные контакта.

### Состав вкладки

Вкладка содержит:
- краткий статус Bitrix24 по контакту
- все прямые поля `Contact`, начинающиеся с `bitrix24_`

### Секции вкладки

1. `Контакт в Битрикс24`
2. `Сделка в Битрикс24`
3. `История в Битрикс24`

Все секции открыты по умолчанию.

## Вкладка `История`

Вкладка `История` показывает timeline истории событий контакта.

### Роль вкладки

Вкладка даёт оператору последовательность значимых событий по контакту.

На первом этапе эта вкладка показывает историю событий контакта, а не полный audit всех изменений полей.

### Состав timeline на этапе 2

Timeline включает high-signal события состояния контакта:
- создание контакта
- появление нового диалога у контакта
- получение телефона контакта
- старт анкеты
- завершение анкеты
- merge / склейка контакта
- значимые события Bitrix24 sync

### Правило по сообщениям

Timeline включает только события состояния контакта; сообщения остаются в dialog page.

### Событие `Появился диалог у контакта`

Это отдельный тип события timeline.

Он используется в двух сценариях:
- создан новый `Dialog`
- после объединения контактов у root-контакта стал доступен дополнительный диалог

Для этапа 2 действует честный контракт:
- обычное появление диалога строится из существующего источника `dialogs.created_at`
- merge-сценарий получает отдельное событие только при наличии подтверждённого источника в runtime
- если отдельного источника нет, merge-кейс отображается через событие merge

### Пагинация timeline

- первая порция: 20 последних событий
- следующая порция: ещё 20 событий
- порядок: обратный хронологический
- способ загрузки: кнопка `Показать ещё`
