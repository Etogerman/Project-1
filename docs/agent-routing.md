# Маршрутизация агентской документации

Этот файл помогает агенту выбрать подходящий рабочий маршрут перед действием,
которое может изменить код, документы, git-состояние, окружения или внешний
контур.

`AGENTS.md` остаётся короткой обязательной конституцией. Маршрутизация не даёт
разрешение на действие, а только указывает, какие небольшие модули или skills
открыть.

## Когда применять

Агент применяет этот файл перед:

- новым code/runtime stream;
- изменением агентской документации, `AGENTS.md` или skills;
- commit, push, PR, ready, merge, deploy или smoke;
- действиями со staging, production, Bitrix24, Open Lines, Telegram, MAX,
  webhook, callback, секретами или миграциями;
- ответом на вопрос о следующем логичном шаге;
- ситуацией, где есть несколько возможных рабочих маршрутов.

## Как пользоваться

1. Использовать активные инварианты `AGENTS.md`.
2. Открыть `docs/workflow/README.md` и определить, существует ли модуль текущего
   состояния.
3. Перед изменяющим действием открыть
   `docs/workflow/shared/work-authority.md`.
4. Определить риск-контур задачи.
5. Определить этап доставки, если задача связана с PR или release.
6. Выбрать основной маршрут из таблицы.
7. Открыть существующий skill и только профильный модуль текущего состояния либо
   запасной источник.
8. Если задача создаёт или меняет документ, влияющий на действия агента, применить
   `docs/agent-docs-lifecycle.md`.
9. Сообщить пользователю выбранный маршрут и ближайшую контрольную точку.

## Статус маршрутов

`Активный` — файл или skill уже существует в активном контуре проекта.

`Запланирован` — маршрут описывает целевую архитектуру, но файл или skill ещё не
принят в активный контур проекта. В этом случае агент использует запасной
источник и сообщает пользователю, что маршрут пока не активен.

Отсутствие запланированного skill само по себе не является блокером. Если
запасной источник даёт достаточно правил для текущего разрешённого уровня, агент
продолжает работу по нему. Если правил недостаточно, агент показывает пробел
пользователю и запрашивает следующий шаг.

Если запланированный skill или reference-файл принят в активный контур проекта,
агент обновляет статус маршрута на `Активный`. Если skill или reference-файл
создаётся в том же изменении, статус маршрута обновляется в этом же diff.

В локальном черновике статус `Активный` для создаваемых в этом же пакете файлов
показывает целевое состояние после принятия всего пакета в активный контур.

## Связанные файлы

Этот файл опирается на `docs/agent-docs-lifecycle.md`. Маршрутизатор становится
активным только вместе с активным lifecycle-файлом или после него.

## Порядок источников

При конфликте или нехватке контекста агент использует источники по порядку:

1. Короткая конституция `AGENTS.md`.
2. Маршрутизатор `docs/workflow/README.md`.
3. Активный skill.
4. Общий профильный модуль и модуль текущего состояния.
5. Запасной источник из таблицы маршрутов.
6. Вопрос пользователю, если предыдущих источников недостаточно.

Skill задаёт рабочую процедуру. Если skill маршрутизирует к профильному
документу, детали берутся из этого документа; skill не переопределяет
канонический документ молча.

## Если подходит несколько маршрутов

Агент выбирает маршрут по порядку:

1. Сначала самый рискованный контур: production, staging, секреты, миграции,
   внешние интеграции.
2. Затем этап доставки: PR, CI, ready, merge, deploy, smoke.
3. Затем предметная область: ТЗ, Laravel, UI, Bitrix24, agent-docs.
4. Затем справочный документ.

Пример: если вопрос про PR с Bitrix24 callback, агент сначала учитывает
интеграционный риск, затем PR-этап.

## Ограничения

Маршрутизация не отменяет `AGENTS.md`.

Выбор маршрута не разрешает commit, push, PR, ready, merge, deploy или smoke.

Если выбранный маршрут ведёт к документу, влияющему на действия агента, агент
применяет `docs/agent-docs-lifecycle.md` при создании, изменении или публикации
этого документа.

Если нужный skill отсутствует, агент не имитирует его существование. Он использует
запасной источник и сообщает пользователю, что skill ещё не активен.

## Результат маршрутизации

После выбора маршрута агент сообщает:

- тип задачи;
- риск-контур;
- выбранный маршрут;
- статус маршрута: активный или запланированный;
- какие документы или skills открыл;
- текущую контрольную точку;
- следующий шаг, который требует решения пользователя.
